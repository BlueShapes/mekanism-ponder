# 字幕の制作単位

字幕のJSON文字列にある `\n` は、作者が選んだ**吹き出しの切り替え境界**です。
同じ吹き出し内の自然な折り返しはMinecraft/Ponderに任せます。
実行時は句点、略語、文字数、フォント幅、行数から境界を推測しません。

```json
{
  "ja": "製品の面を出力にしてください\nアイテムの自動搬出を有効にしてください",
  "en": "Set the product face to Output\nEnable item auto-eject"
}
```

原則は一つの短く完結した文で一つの内容を伝えます。各言語で意味・語順に合う境界を選ぶため、
日英と訳文の表示数を機械的に一致させません。対象、操作、条件、数量、因果関係を保持します。
複数の文を一枠へ詰め込まず、長い文は制作時に短い完結文へ推敲してください。

## 明示的な継続

共通要件67の継続を使う場合も、境界は `\n` で指定します。
前の末尾と次の先頭にUnicodeの `…` を置き、3段以上の中間には両端に置きます。

```text
If the available stress is exceeded…
…and the network stays overloaded…
…all connected machines stop
```

これは自然な条件節と結果を順に読むための制作表現です。
`The processing machine does…` のような主語・助動詞だけの断片には使いません。
省略記号で内容を省かず、各言語で自然な節を選んでください。
文中の `“Waiting…”` のような記号だけでは、新しい吹き出しを作りません。

今回の日英教材は短い完結文で収めており、継続記号を無理に追加していません。
継続形式は2段・3段、孤立・不一致・続きの欠落を回帰テストで確認します。

## 検査と描画

- `tools/caption_units.py` は空欄、既知の不自然な断片、句点、正当な理由のない複数文、継続の対応を制作時に検査します。句点の有無を文法的な完結の条件にしません。略語、小数、版番号、ファイル名、URL、レジストリIDは通常の句点と区別します。
- `tools/test_caption_units.py` は本番のページ境界メソッドをJavaで実行します。異なる仮フォント幅でも同じ明示的単位を返すことを検査します。この仮フォントは実際の表示幅の証拠にはしません。
- 実フォントは検証クライアントで22言語の全字幕を確認します。原則2行・最大3行とし、GUI幅320以上で標準Ponderの180pxの字幕幅を使います。
- アラビア語の実描画幅等を含め、同じ吹き出しの中で自然に改行します。`captionDisplayText` が挿入する改行をページ分割へ戻さず、選択済みの一つの表示単位を一つの標準テキストウィンドウで描画します。
- 長すぎる未知の文が実行時に来ても、途中で切ったり省いたりしません。行数超過は制作時の実フォント検査で検出し、原文・訳文を直します。

`GuideTextLayout.wrap` はアイテム説明の**同じツールチップ内の改行**に使います。
字幕ページの境界には使いません。字幕の読む時間は作者指定の単位数を含めて確保し、
通常の一時停止とキーフレーム操作を保持します。

## 文末記号と色の意図

共通要件69に従い通常の文末句点は付けません。読点、必要な点、継続の`…`は保持します。
0.1.2から0.1.3への句点除去は `python tools/check_punctuation_migration.py` で当時のGitスナップショットを22言語比較できます。
字幕の境界は保持し、アイテム説明だけ既存の文の境界を明示的な改行へ移しています。

`src/main/translations/presentation/<locale>.json` の `units` は125キー（113字幕、12説明）の
各改行単位へ `NORMAL`（白）、`WARNING`（薄い赤）、`HINT`（薄い緑）を指定します。
本文ハッシュ、キー、単位数、意図名を検査します。訳文の単位数が異なる場合はその言語の意味で指定し、
英語の配列を無条件には使いません。本文変更・境界変更は意図も再レビューしてください。
標準PonderのWHITE/RED/GREENを本文に使用し、輪郭の従来色は独立に保ちます。

## 解説の口調

共通要件73に従い、通常操作は操作・仕組み・条件と結果として説明します。
必要な診断、安全確認、対処の依頼は残し、語尾の一括置換や依頼語の件数だけでは判定しません。
要約、字幕、アイテム説明、章の説明を各言語で確認し、表示単位と色の意図も再レビューします。
語句を変えた場合は実フォントで再検査し、過去の句点除去だけの幅証拠を流用しません。
`python tools/check_narration.py` は0.1.3からの模型・ID・章・数値・正式名称の保持を検査します。
文法と自然さの判断は、日本語の修正前後と各言語のレビュー記録で補います。
